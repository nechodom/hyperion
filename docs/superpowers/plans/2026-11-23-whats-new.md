# What's New Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An icon beside the notification bell that lists recently added features, each with a link to where it is configured.

**Architecture:** Entries are a `const` table compiled into `hyperion-web`. `GET /api/whatsnew` serves the newest 10 as JSON, filtered by the session's capabilities. The browser keeps the highest seen id in `localStorage` and paints a dot while a newer one exists.

**Tech Stack:** Rust (axum, serde_json), askama template `base.html`, plain JS in `static/app.js`, `static/app.css`.

**Spec:** `docs/superpowers/specs/2026-11-23-whats-new-design.md`

## Global Constraints

- Administrators and operators only: customers and viewers get no icon and `403` from the feed.
- Panel text is English.
- The feed never contains an entry whose capability the session lacks.
- Feed size: newest 10 entries.
- No stored state: an entry counts as new when it is at most 30 days old.
- Read state is `localStorage` key `hyperion.whatsnew.seen` (an integer id). Every read and write is wrapped in `try/catch`.
- No migration, no new crate dependency.
- The repository is public: no client or site names in entry text.
- Deviation from the spec: an entry has no `version` field. Tags are cut after merge, so the author of a PR cannot know it. `date` carries the same information.

## Review Focus

- `localStorage` throws or is unavailable (private window): the icon and list still work, the dot just shows.
- Stored value is junk (`"abc"`, a negative number): treated as nothing stored.
- Feed request fails or returns 403: icon stays without a dot, the panel says "Could not load", no console exception.
- Session has no capability any entry needs: the panel says "Nothing new yet", no dot.
- Bell dropdown and the new panel both open: opening one closes the other.

**Interfaces:**
- Produces:
  ```rust
  pub struct Entry {
      pub id: u32,
      pub date: &'static str,        // "2026-11-21"
      pub title: &'static str,
      pub body: &'static str,
      pub link: &'static str,        // panel path, starts with '/'
      pub link_label: &'static str,
      pub needs: Option<Capability>,
  }
  pub const ENTRIES: &[Entry];       // oldest first, ids strictly rising
  pub const FEED_LIMIT: usize = 10;
  /// Newest first, at most FEED_LIMIT, only entries `can` allows.
  pub fn visible(entries: &'static [Entry], can: impl Fn(Capability) -> bool) -> Vec<&'static Entry>;
  ```

```rust
#[test]
fn ids_rise_and_dates_do_not_go_back() {
    for w in ENTRIES.windows(2) {
        assert!(w[0].id < w[1].id, "id {} not above {}", w[1].id, w[0].id);
        assert!(w[0].date <= w[1].date, "entry {} is dated before {}", w[1].id, w[0].id);
    }

#[test]
fn every_entry_is_complete() {
    for e in ENTRIES {
        assert!(e.link.starts_with('/') && !e.link.starts_with("//"), "entry {} link", e.id);
        assert!(!e.title.is_empty() && !e.body.is_empty() && !e.link_label.is_empty());
        assert_eq!(e.date.len(), 10, "entry {} date is YYYY-MM-DD", e.id);
        assert!(e.body.len() <= 240, "entry {} body is one or two sentences", e.id);
    }
}

const SAMPLE: &[Entry] = &[
    Entry { id: 1, date: "2026-01-01", title: "a", body: "a", link: "/a", link_label: "a", needs: None },
    Entry { id: 2, date: "2026-01-02", title: "b", body: "b", link: "/b", link_label: "b", needs: Some(Capability::DockerView) },
    Entry { id: 3, date: "2026-01-03", title: "c", body: "c", link: "/c", link_label: "c", needs: None },

#[test]
fn visible_is_newest_first_and_drops_what_the_session_cannot_open() {
    let ids: Vec<u32> = visible(SAMPLE, |_| false).iter().map(|e| e.id).collect();
    assert_eq!(ids, vec![3, 1]);
    let ids: Vec<u32> = visible(SAMPLE, |_| true).iter().map(|e| e.id).collect();
    assert_eq!(ids, vec![3, 2, 1]);
}

#[test]
fn visible_stops_at_the_limit_after_filtering() {
    // 12 open entries and one closed newest: the 10 newest OPEN ones come back.
    // Build with a static array of 13 entries, ids 1..=13, id 13 needs DockerView.
    let ids: Vec<u32> = visible(THIRTEEN, |_| false).iter().map(|e| e.id).collect();
    assert_eq!(ids, (3..=12).rev().collect::<Vec<u32>>());
}
```

- [ ] **Step 2: Share the placement code.** Turn the bell's `position()` into `placeDropdown(btn, dropdown)` at file scope and call it from both IIFEs. No behaviour change for the bell.

- [ ] **Step 3: Script.** On load fetch the feed once. Rules:
  - `seen` = integer from `localStorage['hyperion.whatsnew.seen']`; anything that is not a positive integer, or a throw, means nothing stored.
  - An entry is new when `id > seen`, or, with nothing stored, when its `date` is at most 30 days before today.
  - Dot shown while at least one entry is new.
  - Opening the panel: close the bell dropdown if open, render the list (new entries get class `unread`), store the highest id, hide the dot. The `unread` class stays until the panel closes.
  - Each item: title, body, date as `bell-meta`, and the whole item is a link to `link` with `link_label` shown as the call to action. Text goes in through `textContent` or the file's existing `escape()`.
  - Empty list: "Nothing new yet". Failed fetch: "Could not load", no dot.
  - Closes on outside click and `Escape`, same as the bell. Opening the bell closes this panel.
