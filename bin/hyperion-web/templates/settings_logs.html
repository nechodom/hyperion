How long logs are kept

Every log below records IP addresses, and some record e-mail addresses or what a visitor asked for. Under the GDPR's data minimisation rule they should be kept only as long as they are needed, so each one defaults to 30 days and none is kept forever.

How it is applied

Each node runs a retention pass every hour. It rotates every site's access.log and error.log once a day (the newest copy stays plain as .1, older ones are gzipped) and deletes copies older than the window. The firewall and PHP slow-request logs are rotated by logrotate with the same number of days, and the system journal by a journald drop-in (MaxRetentionSec).

Rows in the panel's database go on the same pass: the Protection page's refused-request samples, ended bans (a ban still in force is kept), the email log and the addresses of old panel sign-ins. The audit log and the notifications are purged on the five-minute scheduler tick; the audit chain is re-anchored at the oldest entry kept, so it still verifies. Export the audit log as CSV first if you need an older copy.

The audit log and the ban history can stay longer than set here. A care report counts a period's plugin updates from the audit log and its blocked attacks from the ban history, so nothing from a period that has not been reported yet is removed: a site on a quarterly report keeps about three months, and one whose report could not be sent keeps everything back to the start of that period. A one-off report over a range you pick yourself is not protected this way.

A shorter ban history means a returning address is less likely to be recognised as a repeat offender. Debian keeps the panel's own nginx log in /var/log/nginx for 14 days, and /var/log/auth.log (when rsyslog is installed) for four weeks; those rules belong to their packages and are left alone.
