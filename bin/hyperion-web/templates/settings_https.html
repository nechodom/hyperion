How sites get certificates
  • A new site starts with a self-signed certificate — enough for nginx to come up.
  • Once its domain resolves to the server, issue a Let's Encrypt certificate from the site's Domains & SSL tab. It is validated over HTTP-01: a file under {{ config.acme.challenge_dir }}{% if chrome.has_nodes %} (this server's path; every node has its own){% endif %}.
  • Wildcards — the preview certificates, or a per-site wildcard from that tab — are validated over DNS-01: you publish a TXT record by hand, unless the domain uses automatic wildcard renewal.
  • Certificates renew by themselves 30 days before they expire. A failed renewal raises an alert.
  • Requests go to Let's Encrypt production; staging is only used when you ask for it on a single issuance.
  • The panel's own certificate is set up under Panel domain.

Before you issue
  • Add a DNS record *.<base> pointing at the node's IP address. On Cloudflare, leave it unproxied (grey cloud): the universal certificate does not cover two-level subdomains.
  • The DNS column looks up a made-up name under each base from that node, so it shows whether the wildcard record exists and points at the node. A valid certificate alone does not make previews reachable.
  • Issuing shows the TXT records to publish at your DNS provider, then validates them over DNS-01. Keep that page open until the certificate is issued.
  • This server holds no DNS credentials, so without automatic renewal a wildcard cannot renew itself: renew it here roughly every 60 days. The status column says when each one expires; reload after a validation and its status reads valid.
  • Every certificate on every node is listed on Certificates.
