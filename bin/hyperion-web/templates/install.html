How enrollment works
  1. Create an invite above. The plaintext token is shown once; only its hash is stored on the master.
  2. Run the printed curl … | sudo bash … command on the new machine.
  3. The install script provisions dependencies, builds hyperion-agent, saves the token and master URL into /etc/hyperion/agent.toml, and starts the service.
  4. Before writing that file it probes this master's TLS certificate from the new machine: verify_tls = true when the certificate verified, verify_tls = false (plus the reason) when it did not, and nothing when the master could not be reached — the agent then verifies any https:// master with a DNS hostname.
  5. The agent calls POST /api/enroll with the token and joins the cluster. It appears under Nodes within about 30 s. If the certificate check fails the agent stops rather than retrying unverified; journalctl -u hyperion-agent -g 'TLS policy' on the node carries the fix. The same command explains a node that stops checking in right after you change this master's certificate.
