Two-factor sign-in

{% if config.cluster.enforce_admin_2fa %}required {% else %}optional{% endif %}

{% if config.cluster.enforce_admin_2fa %} An Administrator or Owner without 2FA is sent to set it up at sign-in and can reach nothing else until they have. {% else %} Administrators and Owners can sign in with a password alone. Every other role is unaffected either way. {% endif %}

Turn it off only briefly, for example during a server move.

When it takes effect

The rule is checked at sign-in. The panel picks up a change within about 30 seconds; nobody who is already signed in is logged out.

Operators, customers and read-only users are never asked for 2FA by this rule. Your own 2FA, password and signed-in devices are on My profile.

Audit log{% if chrome.has_nodes %}Master{% endif %}

Audit log retention

{% if config.cluster.audit_retention_days > 0 %}{{ config.cluster.audit_retention_days }} days {% else %}kept forever{% endif %}

Entries older than this are deleted automatically. Export the log as CSV to keep a copy elsewhere.

How it works

Every change made through the panel is recorded in a tamper-evident BLAKE3 hash chain. A purge re-anchors the chain at the oldest entry kept, so verify_chain still checks what is left.

Kept forever, the log grows by tens of MB a month on a busy cluster. Common choices are 90 days, 365 for stricter rules, or 0 when you export the log off the server and want everything kept here too. Purges run on the regular scheduler tick, about once a minute.

This is the master's log. Every node keeps its own entries and purges them by the audit_retention_days in its own agent.toml, which keeps them forever unless set there.
