    {# ===== Role-aware nav visibility shim ===== Fetches the current session's role from /api/me/role and: 1. Removes nav links the user doesn't have permission for (data-role-min="super_admin" or "admin"). 2. Adds data-role on for any other UI that wants to gate visibility (action buttons in detail pages, etc.). 3. Updates the sidebar user-role pill. 4. Hides any [data-role-min] element across the page — action buttons can use the same attribute to self-hide. Defense in depth: server-side handlers still enforce RBAC, so even if a user disabled JS and manually navigated, they'd hit a 403. This shim is UX polish, not a security boundary. #} {# ===== Application-styled confirm modal ===== Replaces browser-native window.confirm() — that dialog is un-themable, gets blocked by certain browser security modes, and looks like a phishing prompt on macOS.
